## 2. 今天在网站上修掉的三个 bug

### ① UO 面板在内页打开后永远「读取中」

- **真因**：我自己上一轮加的缓存守卫。`loadedAt` 记的是**开始取的时刻**而不是取到的时刻；
  而 cleanup 会**杀掉在飞的那次预热** ⇒ 一打开就杀死挂载时的 `setFeed`，
  守卫又认为"120 秒内取过"不肯重取 ⇒ 永远读取中。
- **修法**：跳不跳过看**手上有没有内容**（`hasData`），不看时间；`loadedAt` 只在成功后才写；
  **依赖变化不许杀在飞的那次**；`inflight` 在 `finally` 里落。
- **提交** `483e327`

### ② 每一页的背景都一样（主页那张）

- **真因**：路由从 hash 改成 browser 之后，`currentPage()` 还在读 `location.hash` ⇒ **恒返回 `home`**。
  连带 `GalleryFrame` 也挂错页的画框。`applyBackground` 又只听 `hashchange`（而 hash 再也不变）。
- **修法**：认 `pathname`（`/chealth` 与 `/pages/x/index` 两种）+ 三个事件都挂
  （`hashchange` / `popstate` / 自己包的 `pushState` 事件）。
- **提交** `7f0e0cf`

### ③ 电影海报「完全不动、没有对应」+ 后来发现的「滑不下去 / 狂闪」

- **海报**：**特异型打架**。`.section__body--enter > view :not(...)` 是一条
  **后代选择器**（特异型 (0,5,1)），把 Reel 的十张海报全顶到 `opacity:1`，
  废掉了 `.reel__card{opacity:0}`（「一次只出一张」那条设计的支点）。
  → 给那 5 条规则加 `:not(.reel__card):not(.reel__t)`。**提交** `dba72a8`
- **滑不下去 + 狂闪**：**同一个原因** —— `ScrollView` 上的 `scrollTop={undefined}`
  **键在**，Taro 的 H5 `ScrollView` 把它当**受控值 0**，每次渲染写回去 ⇒
  滚动位置被反复清 0。→ 网页上改成展开**空对象**。**提交** `856c0e9`

## 4. 部署与验证的固定动作

```bash
# 部署（⚠️ 必须 nohup / run_in_background —— 被 SIGKILL 会带走子进程，整轮白跑）
nohup bash scripts/deploy-pages.sh > /tmp/deploy.log 2>&1

# 指纹：**四处**必须一致
grep -o 'js/app\.[a-f0-9]*\.js' apps/dashboard/dist/index.html          # 本地
~/bin/gh api 'repos/cevtuocjw/CEVTUO-Z/contents/index.html?ref=gh-pages' --jq .content | base64 -d | grep -o 'js/app\.[a-f0-9]*\.js'
curl -s http://120.77.27.128:8081/index.html | grep -o 'js/app\.[a-f0-9]*\.js'   # 国内镜像
# z.cevtuo.com 用 bun 的 fetch（本机 curl 打不通它）
```

⚠️ `raw.githubusercontent.com` **会缓存**（带着查询串都返回旧哈希）⇒ 权威判据是 `gh api`。
⚠️ `gh api` 那条**要剥代理**；`git fetch` 也一样，但**要加 `-c http.version=HTTP/1.1`**（否则间歇性 `HTTP2 framing layer`）。

## 5. ⚠️⚠️ 我犯的错 —— 这一节最该读

### (1) 我一天**猜错了五次**，每次都是"想通了就改、改完用截图才发现错"

| 我"想通"的原因 | 做法 | 结果 |
|---|---|---|
| WXSS 丢了 `inset` 简写 | 改成四条 longhand | ❌ |
| `height:100%` 退化成 auto | 改 `100vw×100vh` + `fixed` | ❌ |
| 元素被 `page` 底色盖住 | 抬 z-index 到 −2 | ❌ **更坏** |
| `onScroll` 让 `active` 有两个来源 | 改成只给小程序 | ❌ |
| `:not()` 抬了特异型 | 撤掉重建 | ❌ |

**最后都是停止推理、改成"写进去读回来"才量到的。**

⇒ **遇到"看起来完全正常但东西不在"，第一件事是设计一个能读回来的量具，不是推理。**
   本项目已经反复验证过这一条（FACT 纪律 2 / 8 / 15）。

### (2) 我三次踩了**同一个**记录在案的坑

- ⚠️ **模板字符串的注释里写反引号 —— 第 4 次**（`page.evaluate(\`…\`)` 会被提前结束、整个脚本崩）
- ⚠️ **`git add $FILES` 在 zsh 下不做单词拆分** ⇒ 整串被当成一个路径，`&&` 链让它**静默跳过提交**
- ⚠️ **`osascript activate` 之后又 `sleep`** ⇒ 那几秒里别的窗口抢回前台，**截图截到别人**，
  量出来的数看起来像"产品变了"

### (3) 我一度把**失败报告成了成功**

早前几轮我说过"小程序渲染正常、数据也通了"——那是真的；
但我**同时**把它算成"背景也解决了"，而背景**从始至终没成立过**。
⇒ 症状清单要**逐条**对，不能因为大部分好了就认为全好了。

## 8. 📌 记下来：网页直接封装成 App 的那条路

今天查实：**小程序这条路被主体类型封死**（个人主体不能用 `<web-view>`，附官方原文）。

**唯一可行的"网页一行不改"的封装** = 出 **Android APK 的 WebView 壳**：

- **Capacitor** 或 **Tauri**（都开源免费，无需审核）
- 壳里就是 `https://z.cevtuo.com`；**网页零改动**
- 这台机器已经在发 APK（`cevtuo-health`）⇒ 工具链和习惯都有
- ⚠️ 和"小程序"不是一回事：**这是要下载安装的 App**，不是微信里的入口
- ⚠️ iOS 需要 Apple 开发者账号（$99/年）；Android 免费

**取舍**：小程序赢在"微信里点开就有"；壳 App 赢在"网页原样、零重写、零维护税"。
两者可以并存。
