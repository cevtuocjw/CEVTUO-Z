# 画廊 —— 换照片、改画框

网站上挂着几张照片：它同时是那一页的**背景**、以及墙上那几枚**画框**里的画。

**主页挂三枚（都在右边），内页各一枚（都在左边），COOF 一枚都不挂。**
六枚画框用**五种做法**，没有两页是同一个样子。

---

## 换一张图（最常用）

```bash
bash scripts/gallery.sh add ~/Downloads/新照片.jpg          # 自动起名 g11
bash scripts/gallery.sh add ~/Downloads/新照片.jpg 海边      # 或者指定名字
bash scripts/gallery.sh list                                # 看画廊里有什么、哪些在用
bash scripts/gallery.sh rm 海边                             # 从画廊和池子里都拿掉
```

然后发布：

```bash
rm -f apps/dashboard/dist/data && bash scripts/deploy-pages.sh
```

> ⚠️ **`add` 会自动压图**（长边 1600px / 质量 72）。原图 6016×3384、单张 8MB，
> 直接拷进去**也能用** —— 那才是危险的地方：页面照样打开，只是首屏等十几秒，
> 而「加载慢」没人会想到是「图没压」。压完约 200KB，**差 40 倍**。

> ⚠️ 名字**别带 `.jpg`**（脚本会加），也**不要有空格和中文** —— 它会变成 URL 里的一段。

> ⚠️ 发布后**线上最多要等 10 分钟**才变（GitHub Pages 的 CDN 给 `index.html`
> `max-age=600`）。这期间线上跑的还是**上一版**，而验证器会报出旧版的数字 ——
> 看起来像「改动没生效」。判据是 `.cevtuo-glass` 在不在。

> ⚠️⚠️ **加一张图只有这一条命令。** `add` 会做三件事：压图 → 写进
> `static/gallery/` → **把名字追加进 `gallery.ts` 的 `PHOTOS`**。
> 第三步是 2026-09-30 补的：在那之前 `add` 只把文件放进去、要人自己去改代码，
> 而漏掉那一步的结果是**「图放进去了但网站上永远不出现」，且没有任何报错**。
>
> ⚠️ **没有「把某张图指定给某一页」这回事**（原来有 `use` 子命令，已删）。
> 读者 2026-09-30 要的是「每次刷新都随机出」，所以挂到哪一页、哪一枚画框
> 是**每次刷新洗牌**决定的，而且**全站不重样**（`Q` 断言守着）。

## 一张表管所有事

`apps/dashboard/src/platform/gallery.ts` 是**唯一**的「哪一页挂什么、放哪张、怎么摆」：

```ts
export const GALLERY = { home: 'g02', coof: 'g03', cnsr: 'g01', paperr: 'g05', chealth: 'g04' };

export interface FrameSpec {
  key: string;              // 'home-a' / 'paperr' / …
  style: FrameStyle;        // 五种做法之一
  side: 'left' | 'right';
  anchor: number;           // 竖直中心落在视口百分之几
  w: number; h: number;     // 宽屏尺寸
  inset: number;            // 离它那一侧的屏幕边多少 px
  photo?: string;           // 这一枚里放哪张（不给就用这页背景那张）
  narrow: { w; h; inset };  // 窄屏（≤700px）那一档
}

export function frames(page): FrameSpec[]   // 空数组 = 这页不挂画框（COOF）
export function gutterFor(page): number     // 宽屏正文要让开多少
```

**背景、每一枚画框的图、在哪一侧、多高、多大、离边多远、正文让开多少 —— 全查这一个文件。**

> ⚠️ 拆成两份的结果不是「差不多」，是背景换了画框没换，而两边单独看都正常。

> ⚠️ 老的五张背景图（`static/home.jpg` 等）**没有删**，留在库里当备用。

（这个项目真的干过一次，整页空白而断言全绿）。

## 改画框的大小 / 位置

**全在 `gallery.ts` 的 `frames()` 那张表里，按枚给。**

| 想改什么 | 改哪个字段 |
|---|---|
| 大小 | `w` / `h`（窄屏用 `narrow.w` / `narrow.h`） |
| 离屏幕边多远 | `inset`（窄屏用 `narrow.inset`；**负数 = 挂出屏幕外**） |
| 纵向位置 | `anchor`（画框中心落在视口百分之几） |
| 里面放哪张 | `photo` |

> ⚠️⚠️ **让位量不用手改。** 它是 `gutterFor()` 从**同一份 spec** 算出来的
> （`inset + w + 30`），写成 `.page` 上的 `--gal-gutter-wide`。
> 这个项目为「四个数是一组、动一个要看另外三个」栽过：让位量 = 框宽 + 离边 + 间隙，
> 两处各写一份的结果是改了一处、另一处压着正文，而**两边单独看都正常**。
> ⇒ 现在 SCSS 里**没有**第二个数字。

> ⚠️⚠️ **窄屏那一档的规则必须写在宽屏规则之后。** 同特异型的 CSS 规则谁赢
> 取决于**顺序**，而媒体查询不增加特异型。这个项目已经栽过**四次**
> （`.home-paperr` / `.home-chealth__rings` / `.chc__gaugebox` / 这里）。
> 上一次的代价：窄屏让位写成 378，正文被推到 x=394 而视口只有 390 ⇒ **整页空白**，
> 而当时所有断言全绿。

### **任何视口都不让位** —— 正文满宽，画框压在它下面

读者 2026-09-30：「**每页的所有的画框都应该是可以跟内容重叠着的，
而不是占据了很多版面**」。

原来宽屏要腾 378px（「画廊」那种留白），窄屏腾 106px。**两份都删了。**
`.section` 的 `padding-left` 回到 `styles/section.scss` 自己的值，
宽屏 48px、窄屏 16px，**和「这一页有没有画框」无关**。

| | 宽屏 | 窄屏 |
|---|---|---|
| 让位量 | **0** | **0** |
| 画框 | 压在正文下面（内容在上） | 同左；内页还挂在屏幕外沿（`inset: -62px`） |
| 正文宽（390 视口） | — | **318px**（让位时只有 234） |

⭐ **P 断言的判据是「不变量」**：内边距不该随「这页有没有画框」变化 ——
COOF（一枚都没有）和其余四页必须**一模一样**。
⚠️ 它换过两次：第一版是「窄屏 `padding-left ≤ 32`」——**魔数**，
而宽屏基础内边距是 48px，于是它在宽屏一直红**而代码是对的**。
调阈值只是把魔数挪个位置；**不变量一个数都不用挑**。

⚠️ **只有内页（左）挂出去**：主页的画框在右，而右边有**翻页轨道** ——
挂出去正好钻到轨道底下，轨道上的圆点会**吃掉指针事件**（按下去没反应）。
同一块地方同时放固定元素和控件时，最先坏的一定是控件。

⚠️ 窄屏上画框被裁掉一部分，但**露出来的面积必须超过一半**（**K 断言**在验）。

## ⚠️ 画框永远在**内容之下**

读者 2026-09-30：「现在的画框在内容上面，要在**内容文字的下面**才可以，
以及在**边栏这些组件的下面**」「**不怕内容压住**」。

⇒ `.gal` 的 `z-index` 是 **−1**，`pointer-events` 是 **`none`**（都有理由，见下）。

### 为什么必须是 −1 —— 不能是 0，也不能更负

| 值 | 结果 |
|---|---|
| `0` 或任何非负 | `position: fixed` 且有 z-index 的元素画在**所有非定位内容之后** ⇒ **盖住正文**。那正是读者抱怨的现象。 |
| `−2`、`−3` | Taro 的页面壳 `.taro_page` 是层叠上下文，而**壁纸**就在 −1。更负的画框会掉到**壁纸底下** ⇒ 整枚看不见。 |
| **−1** | 和壁纸同层，而画框在 DOM 里排在壁纸**之后** ⇒ 同层后画的在上，于是画框盖住壁纸、又被正文盖住。 |

⚠️ 三枚画框**也都是 −1**，它们之间的前后由**数组顺序**决定。
给成 −1/−2/−3 会让后两枚掉到壁纸底下 —— 页面上看就是「少了两枚」。

### ⚠️⚠️ 这个改动**会静默地杀掉动画**

画框降到 −1 之后，`.section` / `.stack` 这些**铺满视口的容器**画在它上面，
而指针事件只发给**最上面那个**元素 ⇒ **画框一个事件都收不到**。

症状是**零**：画框位置对、尺寸对、颜色对，截图上看不出任何异常，**只是不会动了** ——
而「会不会动」正是「要那种高级感的动画」的全部要求。
实测：把鼠标移到画框正中心，`--tx` **一次都没被写过**，`gal--press` 从来没挂上过。

⇒ 修法**不是**把 z-index 调回去（那就退回「压住正文」），而是
**把「谁画在上面」和「谁收到事件」解耦**：

- 指针监听挂在 **`window`** 上，用**几何**判断指针在不在某枚画框里；
- `.gal` 改 `pointer-events: none`（它是装饰，不该抢内容的点击）；
- 每帧**先读完全部矩形、再写全部样式** —— 读写交替会让浏览器强制同步重排，
  而**掉帧正是廉价感的来源**。

⚠️ 副作用：点击**会穿过画框落到内容上**。这是对的（画框是装饰），
但写验证器时要知道 —— 窄屏上画框压在正文上面，测试的 `mouse.down()` 会**真的触发导航**。

## 为什么是「真画框」而不是「加了个 border 的图」

三层叠出来，**少一层就不像框**：

| 层 | class | 作用 |
|---|---|---|
| ① 外框 | `.gal__frame` | 有厚度的一圈。用**渐变**（上亮下暗）而不是纯色 —— 纯色读成「描边」，渐变才读成「一条有截面的木条」 |
| ② 卡纸 | `.gal__mat` | 框里那圈纸。**它是「画框」和「描边的图片」之间唯一的区别** —— 去掉它，照片边上只剩一道深色线，在深色壁纸上糊成一团 |
| ③ 照片 | `.gal__photo` | 比卡纸小一圈，所以卡纸看得见。`object-fit: cover` ⇒ 换横图方图都不变形，只裁 |

⚠️⚠️ **主页那三枚必须各放一张不同的图。** 三枚都放 g02（主页背景本身那张）时，
`float` 那枚和壁纸**糊成一整块**，读不出「这是挂在墙上的另一件东西」——
而 DOM 上一切正常（枚数对、图加载了、方向对）。**是看截图看出来的**，
现在由 **O 断言**守着。

## 交互：为什么「不是假的」

「假动画」的特征是**瞬时**和**均匀** —— 按下立刻缩、松开立刻回，全程没有方向感。
真按一张挂在墙上的画框：**朝手指那一点轻微倾倒** + **反光跟着视角移动** + **松手回弹**。

指针位置写进四个 CSS 变量（`--tx/--ty` 倾角、`--mx/--my` 高光位置），
监听走原生 `addEventListener`**不走 React** —— `pointermove` 一秒 100+ 次，
走 React 就是 100 次重渲染，和合成抢时间，而**掉帧正是廉价感的来源**。
鼠标和触摸走同一条 pointer 路径。倾角**刻意只有 ±3.5°**（10° 以上是卡片翻面，玩具感）。

## 背景：白色遮罩 + 一层流动玻璃

两层，都是「让字读得清」和「让照片看得见」之间的妥协：

1. **遮罩**（`platform/background.ts` 的 `LIGHT_SCRIM` / `DARK_SCRIM`）
   —— 一行 `linear-gradient`，压住照片保住对比度。
   浅色主题原来是 `0.90/0.93/0.97`，照片只剩 3~10% 参与，渲染出来是一块**平的奶油色**
   —— 那不是「照片被调淡了」，是「背景看起来坏了」。现在 `0.58/0.46/0.70`。
2. **玻璃层**（`styles/wallpaper.scss` 的 `.cevtuo-glass`）
   —— 大尺度、缓慢流动的光斑，`soft-light` 混合、`blur(30px)`、38 秒漂移。

**为什么不是「把白色调淡」就完了**：遮罩的注释论证过「浅色主题下正文是近黑的字，
必须压住」。那个论证**是对的，结论错了** —— 让字读得清不止「多盖一点」一条路，
另一条是**别平铺着盖**。磨砂纸和玻璃的区别正在这里：
**纸把底下的东西盖住，玻璃让东西还在、只是没了边。**

⚠️ 玻璃层是 `.cevtuo-wallpaper` 的**子元素**，不是它背景的一部分 ——
背景是 JS 一次写完就不动的，而这一层要**动**。
⚠️ 动画只动 `transform`，**不动 `background-position`** —— 后者要每帧重新光栅化
一大片模糊，手机上直接掉帧，而**卡顿的漂移比不漂移更糟**。
⚠️ `mix-blend-mode` 不会漏到正文上：`.cevtuo-wallpaper` 是 `position: fixed; z-index: -1`，
正好形成层叠上下文。
