# 画廊 —— 换照片、改画框

网站上**每一页**有一张照片，同时是那一页的**背景**、也是页面边上那枚**画框**里的画。
主页的画框在**右**边，内页的在**左**边。

---

## 换一张图（最常用）

```bash
bash scripts/gallery.sh add ~/Downloads/新照片.jpg          # 自动起名 g10
bash scripts/gallery.sh add ~/Downloads/新照片.jpg 海边      # 或者指定名字
bash scripts/gallery.sh list                                # 看现在有哪些、哪页用的哪张
bash scripts/gallery.sh use home 海边                       # 把主页换成它
```

然后发布：

```bash
rm -f apps/dashboard/dist/data && bash scripts/deploy-pages.sh
```

> ⚠️ **`add` 会自动压图**（长边 1600px / 质量 72）。原图 6016×3384、单张 8MB，
> 直接拷进去**也能用** —— 那才是危险的地方：页面照样打开，只是首屏等十几秒，
> 而「加载慢」没人会想到是「图没压」。压完约 200KB，**差 40 倍**。

> ⚠️ 名字**别带 `.jpg`**（脚本会加），也**不要有空格和中文** —— 它会变成 URL 里的一段。

## 改画框的大小 / 位置 / 形状

全在 `apps/dashboard/src/components/GalleryFrame.scss`，而**尺寸只有两个变量**：

```scss
.gal {
  --gal-w: 168px;
  --gal-h: 210px;
}
```

改这两个就够了 —— 里面的三层（外框 / 卡纸 / 照片）全部按百分比跟着走。
**换成横图、方图、竖图都不会变形**：照片是 `object-fit: cover`，只裁不缩。

窄屏（≤700px）另有一套更小的值，也在同一个文件里。

## 为什么是「真画框」而不是「加了个 border 的图」

画框由**三层**叠出来，**少一层就不像框**：

| 层 | class | 作用 |
|---|---|---|
| ① 外框 | `.gal__frame` | 一圈**有厚度**的边。用**渐变**（上亮下暗）而不是纯色 —— 纯色读成「描边」，渐变才读成「一条有截面的木条」 |
| ② 卡纸 | `.gal__mat` | 框里那圈米白色的纸。**这一层是「画框」和「描边的图片」之间唯一的区别** —— 去掉它，照片边上只剩一道深色线，在深色壁纸上糊成一团 |
| ③ 照片 | `.gal__photo` | 比卡纸小一圈，所以卡纸看得见 |

## 交互：为什么「不是假的」

「假的动画」的特征是**瞬时**和**均匀** —— 按下立刻缩、松开立刻回，全程没有方向感。
真按一张挂在墙上的画框：

- 画框**朝手指那一点轻微倾倒**（哪边按得重，哪边陷下去）
- 边框的**反光跟着视角移动**
- 松手时**回弹**一下，不是匀速回原位

实现上：指针位置写进四个 CSS 变量（`--tx/--ty` 倾角、`--mx/--my` 高光位置），
**监听走原生 `addEventListener`，不走 React** ——
`pointermove` 一秒 100+ 次，走 React 就是 100 次重渲染，和浏览器的合成抢时间，
而**掉帧正是「廉价感」的来源**，比动画写得好不好影响还大。
鼠标和触摸走**同一条** pointer 路径，不写两套。

⭐ 倾角**刻意只有 ±3.5°** —— 转到 10° 以上就变成「卡片翻面」，那是玩具感。

> ⚠️ **验证不能看截图。** 截图只有一帧，看不出一帧里有没有方向。
> 用 `bun scripts/verify-gallery.mjs`：它派发真指针事件，读事件前后的四个变量。
> **假动画在 pointermove 前后读出来一模一样。**

## 一张表管两件事

`apps/dashboard/src/platform/gallery.ts` 里的 `GALLERY` 是**唯一**的「哪一页用哪张图」：

```ts
export const GALLERY: Record<string, string> = {
  home: 'g02', coof: 'g03', cnsr: 'g01', paperr: 'g05', chealth: 'g04',
};
export const GALLERY_FALLBACK = 'g06';
```

**背景和画框都查它。** ⚠️ 两处各写一份的结果不是「差不多」，是
**背景换了、画框没换，而两边单独看都正常**。

> ⚠️ 老的五张背景图（`static/home.jpg` 等）**没有删**，留在库里当备用。
> 想把某页换回去，把 `GALLERY` 里那张的值改成 `static/home.jpg` 就行。

## 验证

```bash
# 本地（先起预览服务，见 scripts/preview.sh 抬头）
bun scripts/verify-gallery.mjs

# 线上
bun scripts/verify-gallery.mjs https://z.cevtuogrnd.com
```

**35 条断言**，覆盖：每页有且只有一枚画框 / 框里的图**真的渲染了**（`naturalWidth>0`
—— src 写对不等于图能显示）/ 背景确实换成了画廊那张 / 主页在右内页在左 /
指针移动时倾角和**高光都变**、方向正确、**变换矩阵真的变了**（不是变量变了但没接进
`transform`）/ 离开回到 `0deg` 和 `50%` / 按下挂 `gal--press` 且收 0.975 /
图不可拖动 / reduced-motion 下**过渡关掉但状态照样变**。

> ⚠️⚠️ 这个验证器栽过一次，值得记：一开始只等「有一枚画框 + 里面的图加载完了」。
> 本地全绿，**线上 4 条 D 失败**（内页画框跑到右边）—— 而**线上其实是对的**。
> 真因是 Taro 换页时**旧页面的那枚画框还挂在 DOM 上**，条件在旧元素上立刻满足。
> 同时背景已经是对的（`applyBackground` 挂在 `hashchange` 上，事件发生时就算，不靠
> React 重渲染）⇒ **同一个页面上，一个查得早一个查得晚，于是症状看起来像
> 「背景换了画框没换」**，把人引向「代码有 bug」。
>
> ⇒ **等待条件必须包含「等到的是新的那一个」**，加时间只是碰运气 ——
> 而碰运气的断言在慢机器上会随机变红，那比没有断言更糟。
