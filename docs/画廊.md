# 画廊 —— 换照片、改画框

网站上**每一页**有一张照片，它同时是那一页的**背景**、也是页面边上那枚**画框**里的画。
主页的画框在**右**边，内页的在**左**边。

---

## 换一张图（最常用）

```bash
bash scripts/gallery.sh add ~/Downloads/新照片.jpg          # 自动起名 g10
bash scripts/gallery.sh add ~/Downloads/新照片.jpg 海边      # 或者指定名字
bash scripts/gallery.sh list                                # 看现在有哪些、哪页用的哪张
bash scripts/gallery.sh use home 海边                       # 把主页换成它
```

然后发布：

```bash
rm -f apps/dashboard/dist/data && bash scripts/deploy-pages.sh
```

> ⚠️ **`add` 会自动压图**（长边 1600px / 质量 72）。原图 6016×3384、单张 8MB，
> 直接拷进去**也能用** —— 那才是危险的地方：页面照样打开，只是首屏等十几秒，
> 而「加载慢」没人会想到是「图没压」。压完约 200KB，**差 40 倍**。

> ⚠️ 名字**别带 `.jpg`**（脚本会加），也**不要有空格和中文** —— 它会变成 URL 里的一段。

> ⚠️ 发布后**线上最多要等 10 分钟**才变（GitHub Pages 的 CDN 给 `index.html`
> `max-age=600`）。这期间线上跑的还是**上一版**，而验证器会报出旧版的数字 ——
> 看起来像「改动没生效」。判据是 `.cevtuo-glass` 在不在（见下面「验证」）。

## 一张表管三件事

`apps/dashboard/src/platform/gallery.ts` 是**唯一**的「哪一页用什么」：

```ts
export const GALLERY = { home: 'g02', coof: 'g03', cnsr: 'g01', paperr: 'g05', chealth: 'g04' };
export const GALLERY_FALLBACK = 'g06';
export function gallerySide(page)   // 'right'（主页）/ 'left'（内页）
export function galleryAnchor(page) // 纵向位置 38~57%
```

**背景、画框里的图、画框在哪一侧、画框多高，四处都查这一个文件。**
⚠️ 拆成两份的结果不是「差不多」，是背景换了画框没换，而两边单独看都正常。

> ⚠️ 老的五张背景图（`static/home.jpg` 等）**没有删**，留在库里当备用。
> 想把某页换回去，把 `GALLERY` 里那张的值改成 `static/home.jpg` 就行。

## 改画框的大小 / 位置

全在 `apps/dashboard/src/components/GalleryFrame.scss`：

| 想改什么 | 改哪个数 | 现在的值 |
|---|---|---|
| 大小 | `.gal` 的 `--gal-w` / `--gal-h` | 宽屏 **300×375**，窄屏 **156×195** |
| 离屏幕边多远 | `.gal--left` / `.gal--right` 的 `left` / `right` | 宽屏 **48px**，窄屏左 **-62px** / 右 **60px** |
| 纵向位置 | `gallery.ts` 的 `galleryAnchor()` | 每页不同，38~57% |
| 正文让开多少 | `--gal-gutter-left` | 宽屏 **378px**，窄屏 **106px** |

> ⚠️⚠️ **这几个数是有关系的**：
> `让位量 = 框宽 + 离边 + 间隙`。改框宽而忘了改让位量，两个方向都会坏 ——
> 改小了画框压住正文（**J 断言**会红），改大了正文被推到屏幕外（**M 断言**会红）。
> 上一轮就真的干过：窄屏让位写成 378，正文被推到 x=394 而视口只有 390，
> **整页空白**，而当时所有断言全绿。

> ⚠️⚠️ **窄屏那一档的规则必须写在宽屏规则之后。** 同特异型的 CSS 规则谁赢
> 取决于**顺序**，而媒体查询不增加特异型。这个项目已经栽过**四次**
> （`.home-paperr` / `.home-chealth__rings` / `.chc__gaugebox` / 这里）。

### 窄屏上画框是**被裁掉一部分**的

读者 2026-09-29 允许：窄屏上画框可以挂出屏幕边缘，但**露出来的面积必须超过一半**。
现在挂出 62px，露出 **60%**（**K 断言**在验）。

为什么这么做：手机上为一张画让掉整幅宽度，正文只剩 234px，
而「窄屏内容太窄」正是读者抱怨过的方向。**让一半的画 + 宽一点的正文**，
比「完整的画 + 挤扁的正文」好。

⚠️ **只有内页（左）挂出去**：主页的画框在右，而右边有**翻页轨道** ——
挂出去正好钻到轨道底下，轨道上的圆点会**吃掉指针事件**（按下去没反应）。
同一块地方同时放固定元素和控件时，最先坏的一定是控件。

## 为什么是「真画框」而不是「加了个 border 的图」

三层叠出来，**少一层就不像框**：

| 层 | class | 作用 |
|---|---|---|
| ① 外框 | `.gal__frame` | 有厚度的一圈。用**渐变**（上亮下暗）而不是纯色 —— 纯色读成「描边」，渐变才读成「一条有截面的木条」 |
| ② 卡纸 | `.gal__mat` | 框里那圈米白色的纸。**它是「画框」和「描边的图片」之间唯一的区别** —— 去掉它，照片边上只剩一道深色线，在深色壁纸上糊成一团 |
| ③ 照片 | `.gal__photo` | 比卡纸小一圈，所以卡纸看得见。`object-fit: cover` ⇒ 换横图方图都不变形，只裁 |

## 交互：为什么「不是假的」

「假动画」的特征是**瞬时**和**均匀** —— 按下立刻缩、松开立刻回，全程没有方向感。
真按一张挂在墙上的画框：**朝手指那一点轻微倾倒** + **反光跟着视角移动** + **松手回弹**。

指针位置写进四个 CSS 变量（`--tx/--ty` 倾角、`--mx/--my` 高光位置），
监听走原生 `addEventListener`**不走 React** —— `pointermove` 一秒 100+ 次，
走 React 就是 100 次重渲染，和合成抢时间，而**掉帧正是廉价感的来源**。
鼠标和触摸走同一条 pointer 路径。倾角**刻意只有 ±3.5°**（10° 以上是卡片翻面，玩具感）。

## 背景：白色遮罩 + 一层流动玻璃

两层，都是「让字读得清」和「让照片看得见」之间的妥协：

1. **遮罩**（`platform/background.ts` 的 `LIGHT_SCRIM` / `DARK_SCRIM`）
   —— 一行 `linear-gradient`，压住照片保住对比度。
   浅色主题原来是 `0.90/0.93/0.97`，照片只剩 3~10% 参与，渲染出来是一块**平的奶油色**
   —— 那不是「照片被调淡了」，是「背景看起来坏了」。现在 `0.58/0.46/0.70`。
2. **玻璃层**（`styles/wallpaper.scss` 的 `.cevtuo-glass`）
   —— 大尺度、缓慢流动的光斑，`soft-light` 混合、`blur(30px)`、38 秒漂移。

**为什么不是「把白色调淡」就完了**：遮罩的注释论证过「浅色主题下正文是近黑的字，
必须压住」。那个论证**是对的，结论错了** —— 让字读得清不止「多盖一点」一条路，
另一条是**别平铺着盖**。磨砂纸和玻璃的区别正在这里：
**纸把底下的东西盖住，玻璃让东西还在、只是没了边。**

⚠️ 玻璃层是 `.cevtuo-wallpaper` 的**子元素**，不是它背景的一部分 ——
背景是 JS 一次写完就不动的，而这一层要**动**。
⚠️ 动画只动 `transform`，**不动 `background-position`** —— 后者要每帧重新光栅化
一大片模糊，手机上直接掉帧，而**卡顿的漂移比不漂移更糟**。
⚠️ `mix-blend-mode` 不会漏到正文上：`.cevtuo-wallpaper` 是 `position: fixed; z-index: -1`，
正好形成层叠上下文。

## 验证

```bash
bun scripts/verify-gallery.mjs                          # 本地
VW=390 VH=844 bun scripts/verify-gallery.mjs            # 窄屏（必须单独跑）
bun scripts/verify-gallery.mjs https://z.cevtuogrnd.com # 线上
```

**55 条断言**：

| | 断言 |
|---|---|
| A | 每页**有且只有一枚**画框 |
| B | 框里的图**真的渲染了**（`naturalWidth>0` —— src 写对不等于图能显示） |
| C | 背景确实换成了画廊那张（不是老的五张） |
| D | 主页在右、内页在左 |
| E–G | 指针移动 ⇒ 倾角和**高光都变**、方向正确、**变换矩阵真的变了**、按下收 0.975、离开回 0 |
| H | 图不可拖动 |
| I | reduced-motion：过渡关掉、**但状态照样变**；玻璃的流动停掉、**但玻璃层还在** |
| J | 画框**不压在正文上**（`elementsFromPoint` 取 3×3 个点看底下还有什么） |
| K | 画框**至少一半露在屏幕内** |
| L | 玻璃层**存在**、**真的在流动**（`transform` 随时间变）、混合模式是 `soft-light` |
| M | **正文在屏幕内且有宽度** |

> ⚠️⚠️ **J/K/L 在画框上，M 在正文上 —— 分家是有原因的。**
> 第十四条之前的断言全都盯着画框，于是一个 bug 全都漏掉了：
> 窄屏让位写成 378，正文被推到 x=394（视口 390）—— **整个正文在屏幕外**。
> 而 J 照样绿：画框确实没压住任何东西，**因为没有任何东西可压**。
> **截图是空白，断言是全过。**「让位让够了」的反面是「让过头」，同一个数两头都能坏。

> ⚠️ **元素不在时要报失败，不能抛异常。** 第一版 L 直接
> `getComputedStyle(document.querySelector('.cevtuo-glass'))`，
> 线上还是旧构建（没有这个元素）⇒ 脚本崩溃退出，**后面所有断言一条都没跑**。
> 崩溃会把「一条断言失败」伪装成「验证器坏了」，而这两件事的处理方式完全不同。

> ⚠️ **换页后要等「新的那一枚」，不是「某一枚」。** Taro 换页时旧页面的画框
> 还挂在 DOM 上，只等「有一枚画框 + 图加载完了」会在**旧元素**上立刻满足。
